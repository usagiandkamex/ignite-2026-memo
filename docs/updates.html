THE BRIEF / ABOUT 10 MINUTES

まず押さえたい、今回の変化

今回の共通テーマは、AIを試す段階から、既存システムの中で安全に動かし、運用し、改善し続ける段階への移行です。基盤、データ、従業員体験、セキュリティを別々に見るのではなく、エージェントの権限と業務への影響を含めて設計することが重要になります。

01 / Azure の基盤と運用

Azure Cobalt 200 VMは一般提供となり、AIモデルそのものの推論だけでなく、その周辺で動くエージェントの処理にも向けたArm基盤が広がります。Azure Chaos Studio Workspacesは一般提供です。AKS拡張はBook of NewsではGAとされていますが、製品ドキュメントと公式ブログではプレビューと記載されています。回復性・VM

Azure Monitor health modelsは、個々のアラートだけでなく、依存関係と業務影響を含めた健全性の把握を狙います。SRE AgentにはTeams、複数クラウド、エージェントIDや管理キーなどのプレビューが追加されます。自動化の可否と、調査・変更の承認境界は分けて検討しましょう。運用の発表

AKSではAgent Sandboxによる実行分離、Azure外のサーバーを含むFlex nodes、Foundryから自組織のAKSへの展開がプレビューです。いずれも既存のネットワーク、ID、データ所在地、コストの要件と一緒に評価する必要があります。AI基盤

機密コンピューティングでは、複数GPUにまたがる処理や、データを共有する複数組織間の分析を対象としたプレビューも発表されました。暗号化の対象が保存時・転送時だけでなく処理中にも及ぶか、利用できるハードウェアや運用条件を確認することが出発点です。機密コンピューティング

02 / サーバーとデータ

Windows Server 2028はプレビューです。セキュリティ既定値、ストレージ、管理に加え、企業内でのAI推論を扱います。ただしハイブリッドAIは一部顧客向けの早期アクセスで、ハードウェア要件があります。既存のServer 2025環境から直ちに移行できるという意味ではありません。Server

PostgreSQL互換のAzure HorizonDBは一般提供、Fabric HorizonDBはプレビューです。両者は別の提供形態であり、アプリの配置、サーバーレスの要否、運用と分析の連携から選びます。Cosmos DB、DocumentDB、Azure SQL、Redisも、開発体験・復旧・検索・移行をそれぞれ拡張しています。Azure HorizonDB・Fabric HorizonDB

データベース運用ではFabricのDatabase Hubが一般提供、SQL・PostgreSQLのエージェントはプレビューです。まずはアクセス権の範囲内で性能や健全性の調査を支援し、提案の妥当性と変更手順を人が検証する運用から始められます。Database Hub

03 / Foundry と開発

Foundryでは、複数ターンの評価、本番トレースからのinsights、Agent optimizerが一般提供です。人手の注釈やモデルの追加学習はプレビュー。評価基準を先に定義し、提案された変更を本番に反映する前に人が確認する、という改善サイクルが中心になります。継続改善

Microsoft-Decision-1.1は分類やルーティングなど、選択肢が明確な判断向けのモデルとして一般提供です。コード、画像、安全性などのモデルは製品や提供先ごとに状態が異なります。Copilot SDK 2.0も一般提供となりましたが、モデル名が載っているだけで、すべての利用先でGAになったわけではありません。モデル・SDK

04 / Copilot と業務アプリ

Copilot Managed Runtimeは一般提供となり、対応アプリを管理対象の環境でホストし、必要ならFabricのデータ基盤を使えます。一方、長時間動く個人向けAutopilot、共同作業のWorkspaces、自然言語でアプリを作るCopilot CodeはFrontierでの提供が中心です。一般提供済みの機能と混同しないことが重要です。Runtime・Autopilot

Dynamics 365のSales・ERPプラグインは一般提供、Salesforce in Copilotはプレビューです。Agent 365では支出と価値を確認する機能も拡張されます。業務データに対する既存権限、アクションの承認、利用量課金とライセンスを導入前に確認します。Dynamics・Salesforce・FinOps

05 / Microsoft IQ と Edge

Microsoft IQは、仕事の文脈を扱うWork IQ、業務データの意味を扱うFabric IQ、非構造化データのFoundry IQ、Web情報のWeb IQと、継続改善をまとめる考え方です。元データの権限や意味付けを維持したまま、複数のアプリやエージェントで知識を再利用する方向です。Microsoft IQ

Foundry IQのSharePoint索引は一般提供ですが、knowledge graphやRetriever-1はプレビューです。Edge for Businessではブラウザー操作のスキル化、エージェント専用の管理対象ブラウザー、拡張機能やネットワークの保護が追加されます。機能によって提供状態が異なる点に注意します。Foundry IQ・Edge

06 / Security と Windows

Agent 365、Entra、Defender、Intune、Purviewにまたがり、エージェントのID、アクセス、端末上の実行、機密情報を管理する発表が並びます。Dynamic Agent RiskやMCP Firewallはプレビュー。ローカルAIエージェントのDefender保護は対応製品とライセンスの条件付きで一般提供です。Agent Risk・Entra・Defender

Microsoft PerceptionはBook of Newsと公式ブログで一般提供とされていますが、製品ドキュメントには限定プレビュー表記が残っています。shieldingなどはプレビューで、一時的な保護はパッチの代替ではありません。Windowsのエージェント分離やWindows 365 for Agentsの永続Cloud PCもプレビュー条件を確認します。Perception・Cloud PC・分離

導入順序としては、まず実行主体を把握し、必要最小限のアクセスと監査を整え、その後に利用範囲を広げるのが現実的です。機密データや外部ツールへの接続がある場合は、利用者の権限を引き継ぐだけで安全と考えず、個別のポリシーと承認条件を確認します。
